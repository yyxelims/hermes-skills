# 提交前的"静置延迟"与探针的下线（2026-11-04 收尾）

两件常被忽略的收尾工作：**一个反直觉的性能发现**，和**删掉临时探针时怎么不删断代码**。

---

## 1. 慢速演示变成了真优化：`SUBMIT_SETTLE`

### 现象（用户先发现的）

> 「其实我觉得开了慢速演示这个按钮以后，变得更流畅了，而且轮间隔也变小了，非常奇怪。」

慢速演示的实现在这里是：

```python
self._accept_alert_once()          # 关掉浏览器原生弹窗
self._log("━━━ C: 弹窗「确定」━━━")
if self.slow.get():
    self._stop.wait(0.6)           # 演示用停顿
ok, t_c = self._wait_click_confirm(...)   # 点网页确定 = 真正提交
```

### 为什么它更快

- 点网页「确定」才是**真正触发提交**的动作；原生弹窗刚关的那一瞬，页面还在收尾
- 立刻点确定 → 提交被拖后 → 紧随其后的 iframe 重载也晚开始
- 于是 0.2s 后点主按钮时页面仍在重载 → 一枪必空 → 重试 3~4 次 ≈ 多花 3 秒
- 停 0.6s 再点 → 提交干净 → 重载更早完成 → 下一枪一次命中

**净效果：多花 0.6s，省掉 2~3s 重试**，同时日志里的 `轮间间隔` 也变小（因为不再有重试尾巴）。

### 改法：从演示开关里拆出来做成默认

```python
SUBMIT_SETTLE = 0.6      # 关掉原生弹窗后停这么久再点确认

self._stop.wait(SUBMIT_SETTLE)          # 永远生效，与勾选框无关
if self.slow.get():
    self._stop.wait(0.4)                # 演示开关只负责"让人看得清"
```

勾选框文案同步改成「每个「确定」再多停 0.4s（只为肉眼看清，正式跑可关）」。

### 可复用的判断

> **任何"为了让用户看清"而加的停顿，都要回头问一句：它是不是在补页面的节奏？**

判据：

| 用户反馈 | 结论 | 动作 |
|---|---|---|
| 开了之后"更卡/更慢" | 纯演示用 | 保持可选，默认关 |
| 开了之后"更顺/轮间隔更小" | **功能性参数** | 转正为默认常量，日志说明，勾选框只做额外加时 |

同类信号：用户说"某个看起来多余的操作去掉就出错/保留就顺"——先怀疑它补上了你没发现的页面时序，
不要急着"优化"掉。

## 2. 探针的下线：删功能前先反查引用

用户这次的指令很明确：

> 「把测速和狂点测删掉，慢速演示一定保留！！！！！」

### 删之前必须做的四件事

1. **列引用**：`grep -n "PROBE_\|HAMMER_\|pbtn\|hbtn\|测速\|狂点" 文件`，
   把「按钮 / 方法 / 常量 / 启用禁用语句 / 测试断言」五类一起清。
2. **反查共用件**：探针里那段 JS/常量可能被**留下来的运行逻辑**用着。
   本次 `JS_BUSY`（遮罩采样）名字像探针，实际被 `_mask_state()`（重载门控）引用——
   删了它编译**照样通过**，因为 Python 只在运行时解析全局名，真机一调就 `NameError`。
   教训：**删常量/方法后，必须 grep 出每一处剩余引用，再跑一次带桩的 import/smoke 测试**。
3. **保住运行期开关**：慢速演示、间隔滑块这类用户要用的，不在删除范围内——
   删完在测试里断言它还在（`assert "慢速演示" in src` 及 `slow.get()` 出现次数）。
4. **更新静态自检**：`scripts/check_tk_buttons_enabled.py` 里如果还列着已删的按钮，
   测试会红；改成只查还在的按钮，并额外断言"已删按钮名不再出现"。

### 一个可复制的删除脚本骨架

```python
s = re.sub(r"\n# ---- 狂点实验 ----\n(?:HAMMER_[A-Z_]+ = .*\n)+", "\n", s)
s = re.sub(r"\n# ---- 测速探针 ----\n.*?PROBE_JS = \"\"\".*?\"\"\"\n", "\n", s, flags=re.S)
s = re.sub(r"[ \t]*self\.pbtn = ttk\.Button\(bf, text=\"测速\".*?\n[ \t]*self\.pbtn\.pack\(.*?\)\n", "", s)
s = re.sub(r"[ \t]*self\.(pbtn|hbtn)\.config\(state=tk\.[A-Z]+\)\n", "", s)
s = s.replace("for b in (self.pbtn, self.hbtn, self.dbtn):", "for b in (self.dbtn,):")
s = re.sub(r"[ \t]*# ---------------- 狂点实验 ----------------\n.*?(?=[ \t]*# ---------------- )",
           "", s, flags=re.S)
```

删完统一做三件验证：

```bash
python3 -m py_compile 文件.py            # 语法
grep -c "测速\|狂点" 文件.py             # 应为 0
python3 桩测试.py                        # 断言已删方法不存在 + 保留项还在
```

### 界面收敛后的"标准形态"

去掉探针后，这类连点工具的最小按钮集：

```
[启动浏览器] [开始分行连点] [开始总行连点] [停止] [诊断]
轮间最小间隔 [滑块]
☐ 慢速演示（每个「确定」再多停 0.4s，只为肉眼看清）
```

诊断要留（行内电脑上唯一能自证状态的入口）；测速/狂点/忙碌期这类**一次性探针**在问题定案后
就该删——它们会真的提交单据，留着是风险，不是功能。

## 3. 顺带：多产物版本控制的落地形态

- 脱敏版 → git（有 tag、有提交历史、`grep` 0 命中业务词）
- 明文版 → **不进 git**，落本地快照目录 + 一条脚本：
  `~/.hermes/scripts/snapshot_mingwen.sh` 把 U 盘当前版 / 回溯版 / 新版各存一份带时间戳的副本
- 用户要"某时刻之前的版本"：`git archive <commit> | tar -x -C 目标目录`（快照目录，不动工作区），
  明文版则按提交逐项反推并**再跑一遍桩测试**才交付
