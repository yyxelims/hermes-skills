# LLM 两步判断——相关性+分类不能合并 prompt

## 问题发现

v7 开发中尝试把"是否相关"和"业务分类"合并到一个 prompt：
```
判断以下文章是否相关，并分类。
每篇回答: "[N] 相关|不相关 | 业务线: 信用卡发卡|收单支付|..."
```

**结果**: 相关率从 36% 飙升到 **81%**（518 篇中 423 篇被判为相关），大量逆回购/外汇牌价/央行会晤误判为相关。

## 根因

LLM 在同时判断两个维度（相关性 + 分类）时倾向于宽松——因为分类选项暗示了"这些文章应该能被分类"。

## 解决方案

**必须两步走（两个独立 API 调用）**:

### Step 1: 严格相关性判断
```
判断以下文章是否是金融监管政策、行业动态或公告通知（而非知识科普、业务介绍、部门简介、操作手册）。
仅回答"[N] 相关"或"[N] 不相关"。
注意：XX/YY 都属于相关。
排除：银行卡使用知识/金融科普/部门机构介绍/食品/保健品/体育/教育。
```

### Step 2: 仅对相关文章分类
```
对以下金融监管相关文章分类，每篇回答: "[N] 信用卡发卡|收单支付|消保合规|消费分期|数字人民币|跨境支付|反洗钱|银行监管"
```

## 关键参数
- Step 1: `max_tokens=200`, `temperature=0.1`
- Step 2: `max_tokens=150`, `temperature=0.1`
- 批次大小: 20 篇/批

## 效果对比

| 方案 | 相关率 | 误判 |
|------|:--:|------|
| 合并 prompt | 81% | 大量 |
| 两步走 | 36% | 0% |

## Phase 3.1 二次审查

第一步判为"不相关"的文章中可能有误判。加二次审查：
```
以下文章在第一轮被判定为"不相关"。请严格复查：是否涉及信用卡/收单/支付清算/消费金融/消保？
每篇回答"[N] 错杀"或"[N] 正确"。
```

找回误判的文章直接加入 row_data（不经过完整的 Phase 3 处理）。
