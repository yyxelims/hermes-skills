# 竞赛/答辩 deck 审计 + 按推荐出修订版

面向「改已有 pptx」之外的另一条高频线：用户让你**审计一份快交付的答辩/竞赛 deck**，
把会翻车的地方全挖出来，再**按你自己的推荐出一版修订稿**。

## 触发

- 「这个你给我审计出什么问题了？有哪些改进建议？」
- 「拷问 / 压测 / 审一下这份 PPT」
- 用户在答辩前让你把技术口径、合规口径、对标格局全过一遍

## 审计分级框架（可直接当清单模板）

问题按「一问就塌 → 自己打架 → 位置不对 → 只是难看」四级排，别平铺：

1. **致命级（一问就塌）**：评委一句就能问倒的硬伤。典型：
   - 说不通的模型组合（如「Transformer 底座 + LSTM 微调」——LSTM 当适配层非标准做法，
     且月频流水 6–12 个点连训 LSTM 都不够）
   - 没有训练标签却宣称用了监督方法（如 Stacking 要违约标签，行外流水历史上没留存，
     普惠违约样本少 → 必须改「规则打分 + 专家权重，随样本迭代为监督模型」）
   - 合规红线没处理（见下）
2. **口径级（自己跟自己打架）**：同一件事多页写法不一致，评委逐页一对就穿帮。典型：
   - Agent 数量（第3页「12 Agent 主链」vs 第4页「一个解析 Agent」vs 第7页画成三个独立
     Agent 且超 12）→ 统一成「1 总控 + N 专项 Agent + 3 条并行解析路径」，把纯格式解析器
     从「Agent」里摘出来（Agent 门槛 = 能自主决策/调度/重试/降级）
   - 同名模型跨页不一致（XGBoost → 三模型 Stacking；LSTM → Transformer 底座）→ 改一处
     必须全片同改，否则「一页比一页复杂」
   - 全片仅剩的绝对数字（100%）与已撤的百分比自相矛盾 → 限定为「已对接 X 的 N 类制式文件
     可自动验真」，别笼统写「制式文件 100% 验真」
3. **定位级（位置已被占）**：宣称的「创新点」同业已公开做过。典型「技术架构创新」被某银行
   MOA 多智能体框架、江阴农商行信贷智能体占死 → 改推「数据来源创新」（如「客户申贷时主动
   交上来的行外流水」，同业走自有支付/自建平台/行内数据，没人走这条路）。
4. **演示级（不影响立论）**：整页是图（第 5/7 页只有标题+一句说明，最重信息全在图里）、
   图算法没写清（社区发现用 Louvain 会被问「为何不用 Leiden」）、上下游网络完整性没留余地。

## 合规红线（银行/金融 deck 必查，答辩正面撞）

- 《征信业务管理办法》第十五条：采集企业信用信息不得侵犯**商业秘密** → 客户上下游对手方
  清单是其商业秘密，拿去营销 = 撞线
- 《个保法》第六条/十四条：目的变更须重新取得同意 → 「办贷款」授权改成「拓客」是目的变更
  （第四条把个保限定在自然人，但小微流水里个体户/自然人占比极高，躲不开）
- 《征信业务管理办法》第三条：「分析评价信息」也算信用信息 → 健康度评分/风险标签可能被圈进
  征信业务范畴

三道闸门（选 B 最稳，答辩逻辑最干净）：
- A 授权扩展：授权书增列「对手方信息用于本行客户拓展」条款，客户勾选
- **B 只出名单不触达** ⭐：系统只产内部参考名单，实际触达走工商信息/行业名录等公开渠道
- C 脱敏出画像：不出企业名，只出行业/区域/规模画像

结论话术：「合规是前置约束，不是事后补救——先授权、再挖掘、只出名单不触达」。

## 弹药库（答辩前备好，别临场现编）

- **顺风条文**：抓官方点名要做你这件事的政策（例：网信办/发改委/工信部《智能体规范应用与
  创新发展实施意见》点名「研发金融风控智能体」）→ 放第 1 或第 3 页，比技术形容词管用
- **合规条文**：条号逐条核对，抓自人大网/人行官网全文，不靠转述
- **行业对标表**：列出同业已做的事 + 「撞你哪一页」，评委必问「你和他们差在哪」
- **技术文献**：社区发现分辨率极限（Fortunato PNAS 2006）、Louvain→Leiden、ML 预测打不过
  统计基线（Makridakis 2018）——评委可能拿来问
- **⚠️ 别引用媒体评选**：如「招行授信效率提升300%」「浦发抹香鲸」来自中国金融网评选，非官方
  披露，写进 deck 会被追问出处

## 交付流程

1. 先出**审计清单**（md 落盘）：致命/口径/定位/演示分级 + 弹药 + 「已经做对别改回去」清单
   + 待用户拍板的问题（评委背景、评分维度等根节点问题，因为改法方向相反时不能替他猜）
2. 用户拍板后（常说「按你的想法改一个新版本出来我看看」），**直接按推荐出修订版**，别停在
   清单阶段
3. 修订版做完报改动表（页 → 原 → 改），并点名「没动的两处（等你拍板）」

## 修订版的技术细节（本文件配套 SKILL.md 的补充）

- **插入新页到中间**：`add_slide()` 加到末尾，再 `sldIdLst.remove/insert(idx)` 移到目标位；
  插入点之后所有页页码要 +1（只做 `/9→/10` 全局替换不够，顺移后的序号会错一位）
- **跨 run 改写**：一段话被拆成多个 `<a:r>`（`Transformer + `/`LSTM`/`微调` 是三个 run），
  整段替换设 `p.runs[0].text = 新文本`，其余 run 清空
- **新页配色从原 deck 抽**：`unzip` 出 slide XML，`re.findall(r'srgbClr val="([0-9A-Fa-f]{6})"', xml)`
  拿全片色板，`<a:rPr>` 里 `<a:latin>/<a:ea>/<a:cs>` 拿字体；克隆现成卡片页的几何做底子，
  改文字即可，比从零画+凭空选色更不易「两套皮」
- **程序化自查不渲染**：新页写完后跑几何估算（CJK 字宽≈字号×1.0 估折行高度 vs 框高），
  抓「溢出/越界」，别开 GUI 渲染（用户会反感）

## 讲稿（Word）同步修订 + 「构思」定位

答辩 deck 常配一份逐字讲稿（.docx）。用户改完 PPT 后讲稿往往没同步，会出现「讲的和 PPT 显示的对不上」
（如 PPT 已改「规则打分 + 专家权重」，讲稿还念「XGBoost 随机森林」）——改讲稿前**先重读 PPT 当前文字**，
把口径不一致处一并同步，否则答辩现场评委对照就穿帮。

**docx 最小改动**：按「唯一子串定位段落 → 整段重写」，别逐 run 硬找：

```python
for i, p in enumerate(doc.paragraphs):
    if key in p.text:
        if p.runs:
            p.runs[0].text = 新文本
            for r in p.runs[1:]:
                r.text = ""
```

保留 runs[0] 格式、清空其余 run，比 add_run 更不丢原段落样式。同样输出新文件（vN），不覆盖用户手改过的原稿。

**「构思」定位（用户明确要求，竞赛/答辩必用）**：把整个介绍框成「创新构思 / 想法」，不是「已落地的系统」。
动词用「构想 / 设计 / 计划 / 准备」，别说「已经做了 / 已实现」；措辞尺度「预计 / 可实现 / 计划」。
创新支柱要讲全三条，讲稿最常漏第一条：
1. **数据来源差异化**（同业没人用的入口，如「客户申贷时主动交上来的行外流水」）——PPT 第3页若有
   「数据来源创新」标签，讲稿必须点出来呼应，否则「创新」立不住
2. 一份材料多次复用（理念创新）
3. 多 Agent 协同（技术构思，讲单 vs 多的区别与联系，别再复述架构）

**页码双向都坏**：插页要全局改总数 + 顺移页 +1；删页（如用户删掉你加的合规页）后页码会残留
「X / 10 但实际 9 页」，封底「10 / 10」是最显眼的穿帮点。交付前正则核对「实际页数 == 最后一页显示的总数」。
