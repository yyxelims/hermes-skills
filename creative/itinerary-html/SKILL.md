# itinerary-html

把任意行程数据（火车票、酒店订单、景点列表、口述路线）**可视化成可交互 HTML**。

## 触发场景

- 用户说："把这些火车票 / 景点 / 酒店做成一个 HTML 攻略页面"
- 用户说："我想可视化我的行程" / "做成地图形式"
- 用户粘贴订单截图、Excel 表、口述行程，并要求"做成网页"

## 不适用

- 简单 Markdown / Notion 清单（文档工具足够）
- 实时导航（用高德/百度地图 App）
- 多人协作编辑（需要后端 + 实时同步）

## 输入形式（任何一种都可以）

| 形式 | 例子 | 处理 |
|---|---|---|
| Excel/CSV | 酒店订单表格 | 解析 + 逐行核实 |
| 文字清单 | "D1 上午 8:00 景点 A 下午景点 B..." | 拆解 + 核实 |
| 高德分享 | 一堆 `https://uri.amap.com/marker?position=lng,lat&name=...` 链接 | 直接用链接里的坐标 |
| 截图 | 12306 / 携程订单截图 | 用 OCR 或问用户 |
| 口述 | "我下周去杭州 3 天，主要看西湖和灵隐寺" | 反问补细节 + 提建议让用户选 |

## 交付物

**两个独立单文件 HTML**（用户后续可直接发给他人/部署到任何静态托管）：

- `<行程名>.html` — 桌面三栏（时间轴 / 地图 / 详情），适用 ≥1280px
- `<行程名>-mobile.html` — 单列 + 浮层，适用手机

均支持：
- Day 切换（横向 pill 或折叠卡片）
- Tab 切换（全程 / 交通 / 酒店）— *可按需删除*
- 高德地图 marker + 自动聚焦
- Open-Meteo 天气（无需 Key）
- 详情浮层 + 跳高德 App（仅国内）
- 导出攻略为 PNG（仅桌面）

## ⚠️ 三条铁律（违反即返工）

### 1. **绝不瞎编任何数据**
- ❌ 凭印象编坐标、地址、电话、票价、营业时间、店名
- ❌ 凭印象编景点名、路线、转乘信息
- ✅ 拿不准的**直接问用户**
- ✅ 坐标必须用高德 POI 查询 API 验证（国外行程用 Google Geocoding / Nominatim，**另行扩展**）
- ✅ 用户没提到的细节（票价、营业时间），就**留空**，不要写"约 ¥X"

### 2. **凡涉及用户隐私/订单的数据**
- ❌ 不允许从记忆里推断（"上次去 XX 也是住这家"）
- ✅ 必须由用户提供，或写"⚠️ 待用户提供"

### 3. **不确定就留空 + 标注**
- 拿不准的字段 → 在 desc 写 `⚠️ 待用户提供`
- 搜不到的 POI → 问用户具体店名，或从行程删掉
- 不要为了"完整性"硬填假数据

## 工作流程（5 步）

1. **解析输入**：把用户给的任意形式行程 → 拆成 `[(day, time, type, name, desc)]` 的候选列表
2. **核实坐标**：所有候选 POI 走 `references/coord-workflow.md` 的高德 API 流程
3. **澄清盲点**：把搜不到的、地址残缺的、缺细节的列出来问用户
4. **填充模板**：从 `assets/template-*.html` 复制，填入核实后的数据
5. **自检交付**：按 `references/qa-checklist.md` 逐项过

## 关键文件

| 文件 | 何时读 |
|---|---|
| `references/coord-workflow.md` | 必读。**第一步就要读**，所有坐标都用这里的工作流查 |
| `references/data-schema.md` | 复制模板后填数据前读 |
| `references/qa-checklist.md` | 交付前逐项过 |
| `assets/template-desktop.html` | 复制起点，已剥离示例数据，只留结构 |
| `assets/template-mobile.html` | 同上，移动版 |

## 配色规范（10.0 墨绿扁平，**用户没要求换色就保持**）

- `--ink: #1f3d34`（主墨绿）
- `--bg: #f7f8f6`（背景暖灰）
- `--accent: #c97b4a`（必看强调橙）
- 类别色：`--t-transit: #2563eb` / `--t-scenic: #2a9080` / `--t-food: #c2410c` / `--t-hotel: #6d28d9` / `--t-must: #a03a2e`
- 零圆角（除 Day 切换条），1px 描边，硬阴影
- 字距 -0.2 ~ -0.6px（高级感关键）

如果用户明确说"换个风格 / 不要绿色 / 想要更鲜艳"，**整个配色模块需要重写**，不要只改主色（深绿配橙色换成其他色系会破坏对比）。这种情况让用户先确认新色系再继续。

## 不要做的事（无论什么行程）

- ❌ 不要把示例（北京-佛山-长沙）的数据留在生成的 HTML 里
- ❌ 不要给地点名后加 emoji 装饰（如 `🦁 祖庙` → `🦁` 已用于类型识别，**地名本身不要再加 emoji**）
- ❌ 不要写"小镰仓""绝美""超赞"等营销/网梗词
- ❌ 不要在 desc 里给景点评分（"4.5 分""五星"）
- ❌ 不要预测天气、温度、价格、营业时间

## 扩展点（不内置，按需加）

- **国际行程**：高德 POI 不支持海外，需换 Google Geocoding API + OpenStreetMap，**完全不同的代码结构**
- **多人协作**：需要后端，本 skill 不涉及
- **PDF 导出**：用户问就用浏览器打印，不需要额外代码
- **预算统计**：如果用户提供了花费数据，加一个 `.budget-summary` section 展示
- **行李清单 / 待办**：作为附加 section 加到详情面板
