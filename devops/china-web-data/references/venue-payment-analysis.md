# 文旅场景支付适配分析

对一批文旅/商业场景，系统评估微信生态现状和智付通支付可介入方向。

## 核心约束（最重要）

**已有小程序的场景 → 不能往里面加支付，也不能再建一个小程序。**
只能通过工银e生活导流到对方小程序。

**没有小程序的场景 → 可以从零搭建小程序并内置智付通作为支付通道。**

分析之前必须先搞清楚每个场景的微信生态现状（有没有公众号？有没有小程序？有没有H5购票？），再判断哪些场景可介入。

## 分析流程

### 步骤 1：读取场景清单

从 Excel 读取场景列表，通常包含：单位名称、运营单位、建设情况、内容提炼、可介入方向等列。

### 步骤 2：搜索微信生态现状

使用百度 AI 搜索（skill: baidu-ai-search）逐个搜索关键场景：
```
python3 /Users/you/quant-lab/baidu_search.py "场景名称 微信公众号 小程序"
```

也可以尝试搜狗微信搜索 `weixin.sogou.com`（但注意反爬）。

重点确认：
- 是否有独立公众号？公众号名称和 biz_id 是什么？
- 是否有独立小程序？小程序名称是什么？
- 是否有 H5 购票/预约页面？
- 是否被某城区级聚合平台覆盖（文旅某城区/北京某城区公众号、百园地图/精彩消费在某城区小程序）？

### 步骤 3：逐场景判断支付适配

对每个场景，判断以下维度：

| 维度 | 判断标准 |
|------|----------|
| 涉及支付 | 是否有商业交易环节？纯展示/文保/政务/市政=否 |
| 票务 | 是否卖门票/活动票？ |
| 餐饮 | 是否有餐饮服务（扫码点餐/结账）？ |
| 民宿 | 是否有住宿（预订+押金预授权）？ |
| 停车 | 是否有停车场（无感支付）？ |
| 零售商城 | 是否有文创/商品售卖？ |
| 会员系统 | 是否适合做会员储值/积分？ |
| 微信公众号 | 是否已有公众号？或可新建/增强？ |
| 微信小程序 | 是否已有小程序？或可从零搭建？ |
| 工银e生活引流 | 是否适合上架工银e生活发券引流？ |

符号约定：
- **★** = 重点适用（高频交易场景，强推荐）
- **✓** = 适用（有场景但优先级一般）
- **—** = 不适用

### 步骤 4：应用核心约束修正

遍历所有场景：
- 如果该场景**已有成熟小程序**（如园博园、王佐全域旅游、汽车博物馆、花卉大观园等）→ `微信小程序=—`，所有支付列（票务/餐饮/民宿/停车/零售商城）如果依赖于自建小程序则也标 `—`
- 如果该场景**没有小程序** → `微信小程序=★/✓`（可建），支付列按实际判断
- 不管有没有小程序 → `工银e生活引流` 都能做（导流到对方已有小程序）

### 步骤 5：写入 Excel 并格式化

新增列追加到原 Excel 中，保留原有列不变。

格式化规范：
- 表头：浅灰底色 `#f1f5f9`，加粗
- ★ 单元格：红色粗体 `#dc2626` + 浅红底色 `#fef2f2`
- ✓ 单元格：绿色 `#16a34a` + 浅绿底色 `#f0fdf4`
- — 单元格：浅灰 `#cbd5e1`
- 涉及支付「是」：绿色粗体 + 浅绿底色
- 涉及支付「否」：灰色 + 浅灰底色
- 已有小程序的行：淡蓝底色 `#eff6ff` 标记（原始列）
- 可建小程序的行：淡绿底色 `#f0fdf4` 标记（原始列）
- 创建第二个 Sheet「功能矩阵统计」，包含统计总览 + 可建列表 + 已有列表

## 搜索渠道速查

| 渠道 | URL / 方式 | 用途 | 限制 |
|------|-----------|------|------|
| 微信搜一搜 | 微信 App 内顶部搜索 | 搜公众号/小程序/文章 | 手动，无法批量 |
| 搜狗微信搜索 | weixin.sogou.com | PC 端搜公众号和文章 | 有反爬，需浏览器 |
| 百度 AI 搜索 | 百度千帆 API | 批量搜索中文资源 | 每日 80 次限额 |
| 新榜 | newrank.cn | 公众号排行榜/筛选 | 需付费 |

## 常见某城区聚合平台

分析某城区场景时注意以下聚合平台——覆盖在它们下面的场景，不等于有自己的独立公众号/小程序：

- 公众号：**文旅某城区**（某城区文旅局）、**北京某城区**（某城区政府）、**某城区创森**
- 小程序：**精彩消费在某城区**、**森林城市 百园地图**、**王佐全域旅游小镇**、**北京园博园小程序**
- H5：北京景区购票服务平台、各景区 OTA 页面

## 已知已有小程序的某城区场景（不能介入）

- 宝藏某城区（精彩消费在某城区小程序 + 文旅某城区公众号）
- 花卉大观园（北京花卉小程序 + AI 导览小程序 + 公众号）
- 王佐全域旅游小镇（王佐全域旅游小镇小程序）
- 卢沟桥文化公园（购票小程序 + 公众号）
- 北京园博园（北京园博园小程序 + DeepSeek AI + 公众号）
- 北京汽车博物馆（玩转汽博小程序 + 公众号 + 多平台购票）

## Pitfalls

1. **最大陷阱**：不确认微信生态现状就直接标支付可介入。必须先用百度搜索确认有没有小程序。
2. 聚合平台覆盖 ≠ 有自己的小程序。被"文旅某城区"公众号报道过，不等于这个场景自己有公众号。
3. 建设情况为"意向谋划"/"概念规划"的场景，运营主体可能未定，支付适配只能作为远期规划。
4. 纯展示/文保/政务/市政类场景不涉及支付，不要硬推。
5. 百度 AI 搜索每日 80 次限额，54 个场景需要分批搜索，优先搜 ★★★ 和 ★★ 的场景。
