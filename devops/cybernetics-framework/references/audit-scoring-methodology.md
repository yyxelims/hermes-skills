# Skill审计评分工法

## 五维度评分体系

每个skill在5个维度上评分（1-5分）：

### 1. 闭环完整性（映射原则1、6）
- **5分**：完整的「执行→验证→修正→再执行」循环，含自动化验证步骤
- **4分**：有验证步骤但依赖人工触发
- **3分**：有线性工作流但缺少验证环
- **2分**：纯CRUD或工具手册，无验证环节
- **1分**：无任何反馈机制

### 2. 稳定性（映射原则4）
- **5分**：含容错、fallback、错误恢复、边界条件处理
- **4分**：有troubleshooting指南和已知pitfalls
- **3分**：有基本错误处理说明
- **2分**：仅提及可能需要检查
- **1分**：无任何稳定性考虑

### 3. 可观测性（映射原则5、13）
- **5分**：有结构化metrics、实时监控、多维度状态检查
- **4分**：有JSON输出、状态检查命令、错误码
- **3分**：有文本输出可被下游解析
- **2分**：依赖人工目视检查
- **1分**：无可观测反馈信号

### 4. 最优化（映射原则7）
- **5分**：有自动优化策略（参数搜索、调度优化、自适应）
- **4分**：提供多策略选择指南和优化建议
- **3分**：有基本性能/效率建议
- **2分**：仅提供可行方案
- **1分**：无优化考虑

### 5. 跨域性（映射原则10）
- **5分**：方法论完全领域无关，可迁移到任意场景
- **4分**：核心方法论可迁移，但实现绑定特定领域
- **3分**：部分方法论可泛化，但主要限定领域
- **2分**：高度特化于单一工具/平台
- **1分**：完全不可迁移

## 输出格式

审计结果保存为JSON数组，每个skill一个对象：

```json
{
  "name": "skill-name",
  "category": "category",
  "closure": 4,
  "closure_note": "简短说明",
  "stability": 4,
  "stability_note": "简短说明",
  "observability": 4,
  "observability_note": "简短说明",
  "optimization": 3,
  "optimization_note": "简短说明",
  "cross_domain": 4,
  "cross_domain_note": "简短说明",
  "principles": [1, 4, 5, 8, 13],
  "issues": "关键缺陷和改进建议"
}
```

`principles` 数组记录该skill体现（而非缺失）的核心原则编号。

## 审计流程最佳实践

1. **分批读取skill**：使用 `skill_view()` 并行读取（每批8个），避免顺序读取导致超时
2. **路径名解析**：`skills_list()` 返回的名称可能与 `skill_view()` 的路径名不同（如 `segment-anything-model` → `segment-anything`）。若 `skill_view()` 失败，用 `search_files(target="files", pattern="SKILL.md")` 查找实际文件路径，再用 `read_file()` 直接读取
3. **分级输出**：同时生成详细JSON（保留所有维度）和摘要表格（仅展示总分和关键发现）
4. **识别系统性模式**：完成后统计每类的平均分、最佳/最差skill、跨类别的共性缺陷
5. **保存路径**：`~/.hermes/plans/cybernetics-audit-YYYY-MM-DD.json`

## 已知的审计模式

### 强项类别
- **software-development**：TDD、subagent review、systematic debugging等skill天然嵌入反馈闭环，平均分最高
- **MLOps评估/优化**：DSPy、W&B、OBLITERATUS等有自动优化机制的skill评分高

### 弱项类别（共性缺陷）
- **productivity工具类**：普遍缺少「操作后自动验证」步骤（如create后未确认、send后未检查）
- **纯工具手册**：obsidian、nano-pdf、polymarket等缺乏反馈机制

### 被最频繁忽视的原则
- **P3（数学建模）**：历史上多轮审计（05-28, 06-01, 06-02）覆盖度为 0%。06-03 审计首次突破至 14%——部分 data-science/mlops skill 被识别为体现数学建模思想。但仍是低覆盖原则。
- **P11（技术科学定位）**：覆盖度持续在 8% 左右，与 P3 形成「理论层双薄弱」——skills 停留在操作手册或纯方法论两极，缺少桥接两者的中间层。
- **P14（理论实践不可偏废）**：覆盖度最低（06-03: 3%），绝大多数 skill 要么纯操作手册、要么纯方法论。
- **P12（大系统观）**：skill间集成和全局协调的视角普遍缺失（06-03: 7%）。
